# 无状态分析扩展

## Problem Statement

插件提供研究和计算能力，调用方不一定保存自选股、账户或历史状态。新增能力应在一次调用中完成，使用显式输入，复用现有数据工具，不要求模型维护账户或插件启动后台服务。

## Solution

增加同行比较、公告财报证据比较、组合风险、仓位预算、事件研究、回测稳健性及快照比较。数据采集沿用现有工具；调用方传入已取得的结构化数据或正文。回测验证直接复用现有引擎。四个宿主暴露相同接口。

## User Stories

1. 用户提供多家公司同口径指标，查看差异、排名与缺失项。
2. 用户能够识别报告期、指标单位、币种不一致导致的不可比项。
3. 用户提供当前及前期公告正文，获得带行号的变更证据，再由 Skill 解读。
4. 用户提供同口径财务指标，获得绝对变化与相对变化；零基数和负基数不伪装成普通增长率。
5. 用户一次性传入多只持仓与现金，查看市值、盈亏和集中度。
6. 用户显式提供外汇转换率，按统一基准币种汇总。
7. 用户可以提供同币种收益历史，查看日期对齐后的相关性，缺失不填零。
8. 用户提供资金、可用现金、入场价、止损价、风险预算和交易单位，计算数量。
9. 仓位预算同时受现金、单笔风险及最大仓位约束，并计入费用假设。
10. 用户提供事件日期、股票和基准价格序列，获得交易日窗口收益及超额收益。
11. 非交易日事件映射到下一交易日，窗口不足或重叠明确说明，不推断因果。
12. 用户提供完整 DSL 策略、历史 K 线及事先确定的候选参数，获得滚动训练/测试、参数敏感性与跨标的结果。
13. 测试窗口不参与参数选择，所有候选和失败项均可审计。
14. 用户传入新旧快照，获得新增、删除、变化、缺失及恢复项目。
15. 无效输入得到 JSON 错误和非零退出码，不输出 traceback 或用户原始内容。
16. 四个宿主使用相同参数和 CLI，现有工具行为保持兼容。

## Implementation Decisions

- 新能力使用显式 JSON 输入，宿主通过权限受限、调用后清理的临时文件传入 CLI（避免 Windows argv 长度限制），也支持 stdin；不保存个人数据。
- 计算函数与 CLI 是公共接口。输入值、单位、日期、价格、重复标的及数量均在 Python 边界验证。
- 同行比较仅对同口径指标排名；不把缺失值记作零，不生成无依据的综合买卖评分。
- 财报解读依赖明确来源的正文和结构化指标；正文比较产生可定位证据，经济含义由共享 Skill 解释。
- 组合与仓位计算第一版为现货多头；汇率表示每单位持仓币种对应多少基准币种。
- 事件研究采用事件前一股票交易日收盘作为基准，事件日为不早于输入日期的首个股票交易日；基准缺端点数据时标记不可用，不移动事件日期。收益为买入持有收益差。
- 事件研究和回测验证同时支持代码/日期直接采集与显式历史数据，两种模式互斥。保留实际覆盖范围，避免模型重述大量K线。
- 回测稳健性固定使用次日开盘成交；滚动训练窗口内选择参数、后续不重叠测试窗口验证，并保留模拟限制。
- 新能力接入现有综合分析、事件驱动、成长质量、回测 Skills，不新增宿主服务、依赖或账户系统。

## Testing Decisions

用户已确认：优先验证 Python CLI 的 JSON 输入输出、结果和错误，再验证四个宿主注册和参数映射。测试通过公开接口，使用人工可核算的小样本和现有 K 线 fixture；先失败再实现，逐项纵向交付。

## Out of Scope

券商连接、交易执行、账户/自选股持久化、通知、调度、PDF OCR、新的行情来源、跨市场现金结算。Skill 必须明确：PDF 正文需宿主提取，只有标题和链接不等于读取全文。

## Further Notes

历史样本和相关性不保证未来收益；回测验证保留复权、市场冲击与交易约束限制。外部 API 和真实模型测试与离线验证分开报告。
