# 分析可靠性优化验收

范围：共享 Python 核心、四个薄适配器、相关 skills/README 和现有测试。不提交、不发布，不增加运行时依赖。

1. 采集错误：综合采集保留安全的 CLI JSON 错误，区分超时/空输出/非法 JSON；旧调用者的 None 失败约定兼容。
2. 成交：默认前一交易日收盘信号、下一有效交易日开盘成交；保留显式 same_close 以复现旧结果。零成交量不成交；一字涨跌停按提供的限制价保守阻止；输出模型及限制。
3. 超时：一份命令预算供 Python 和四端使用，外层留出退出余量；快照 240 秒、选股按候选数及 6 个 worker 的批次计算（默认 20 个候选为 1830 秒）、13F 300 秒。
4. 行情证据：保持数组/字典形状，添加获胜来源、UTC 采集时间、提供方时间（缺失为未知）及复权口径；不把日历推断当成提供方时间。
5. 最终质量：固定证据案例验证缺失、过期、冲突、样本不足和完整数据；真实 LLM 评测单独标记，不把离线检查当成模型效果。报告展示证据和限制，信号复盘按已有 source 分组。
6. 选股覆盖：每个候选输出可用/缺失因子、覆盖度和生效权重；缺失不能伪装成零分证据。

验证：每项先运行失败回归，完成后全量离线 pytest、ruff、TS 类型检查、四端注册/确定性往返、构建和打包检查。实时源/真实模型需要外部条件，结果分别说明。
